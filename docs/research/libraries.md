## Missed facts
- The IMAP IDLE service type matters more than the library. For apps targeting API 35+, dataSync foreground services are limited to 6 h per 24 h; after that onTimeout() is called and new starts throw ForegroundServiceStartNotAllowedException. BOOT_COMPLETED receivers may not start dataSync FGS. FairEmail and Thunderbird both run IMAP push as foregroundServiceType="specialUse" with PROPERTY_SPECIAL_USE_FGS_SUBTYPE. Thunderbird uses dataSync only up to maxSdk 33. — WHY: The report's 'platform FGS for IDLE' must be specialUse (Play policy justification needed) or it will die after 6 h. This drives the push design and the manifest.
- Gmail supports CONDSTORE (and COMPRESS=DEFLATE, MOVE, UIDPLUS, SPECIAL-USE, UTF8=ACCEPT) after login, but NOT QRESYNC, and there are no plans to add it. Expunge detection on Gmail needs a UID list diff (or X-GM-MSGID matching). — WHY: The Angus QRESYNC path (ResyncData) only helps on Riseup/Dovecot. The sync engine needs a CONDSTORE-only fallback for Gmail, which adds battery and data cost on large folders.
- Angus's default mail.imap.auth.mechanisms is 'PLAIN LOGIN NTLM', which excludes XOAUTH2. OAuth only works if you set mail.imap(s).auth.mechanisms / mail.smtp(s).auth.mechanisms = XOAUTH2. — WHY: Gmail OAuth silently falls back to PLAIN with a token as the password and fails.
- jsoup Safelist.relaxed() removes cid: image sources (verified: <img src='cid:abc'> becomes <img>) and removes every style attribute. HTML mail depends on inline CSS. You need a custom Safelist: addProtocols("img","src","cid") (or rewrite cid: before cleaning) and allow style (then remote url() in CSS must be blocked by CSP / setBlockNetworkLoads, not by jsoup). — WHY: With the recommended pipeline as written, inline images disappear and newsletters render unstyled, which is a usability regression.
- Bouncy Castle 1.86 (2026-09-11/15) fixes three OpenPGP CVEs: CVE-2026-71886 (certification accepted from a subkey without certify flag), CVE-2026-71887 (signature from a signing subkey without cross-certification), and CVE-2026-85515 (message truncation not reported, bypassing the SEIPDv1 integrity check). 1.85 also fixed CVEs. PGPainless 2.0.4 still pins BC 1.84. — WHY: If PGPainless is chosen, force bcprov/bcpg/bcutil-jdk18on 1.86 in Gradle and run the PGPainless tests, or the app ships known OpenPGP verification flaws.
- On Android 12+ with target 31+, android:allowBackup="false" may not stop device-to-device transfer on some OEMs. You also need android:dataExtractionRules with <device-transfer> excludes for the DB and prefs. — WHY: The report's credential guidance relies on allowBackup=false only. The encrypted DB and its wrapped key blobs could still be copied by D2D (keys stay behind, but metadata and FBE assumptions change).
- Angus main has unreleased fixes after 2.0.5: BDAT/CHUNKING lost leading dots (#210, 2026-10-09), and the text_xml handler resolved XML external entities on writeTo (#204, 2026-10-06). Both Gmail and Riseup advertise CHUNKING. — WHY: Leave mail.smtp.chunksize unset (the default, no BDAT) with 2.0.5. Never send text/xml parts through the handler. Watch for 2.0.6 or 2.1.0.
- No Gmail OAuth redirect path is both clean and policy-compliant for a new non-GMS Android app. Android-client custom schemes are 'no longer supported' and loopback is deprecated for Android/iOS client types. The remaining options are unverified for 2026: a Desktop-type client with a 127.0.0.1 loopback listener in the app (works technically, against Google's mobile guidance), or a Web-type client with an https App Link redirect. The second needs a domain serving a static assetlinks.json and a client secret in the APK. FairEmail's providers.xml references oauth.faircode.eu/.well-known/assetlinks.json. — WHY: The 'manual PKCE behind a flag' recommendation cannot be shipped until one of these is chosen. Hosting a static assetlinks.json may conflict with the 'no self-hosting' rule.
- SQLCipher-android's crypto is libtomcrypt (portable C), not OpenSSL/BoringSSL. Its consumer rules keep all of net.zetetic.database.** and LOAD_EXTENSION is compiled in. — WHY: The 5–15% overhead figure may be higher on arm64 without hardware AES paths. Benchmark on device. The load_extension SQL function stays off unless enabled per connection, so do not enable it.

## Implications
- Measured DEX after R8 (R8 9.2.4, min-api 26, exercised API surface only; real apps vary by about ±30%): Angus Mail ≈314 KB, mime4j ≈149 KB, jsoup ≈200 KB, PGPainless + BC ≈942 KB, AppAuth ≈39 KB (+ AppCompat). Native: bundled SQLite 1.28 MB per ABI, SQLCipher 2.10 MB per ABI (arm64). Ship an App Bundle so each user gets one ABI.
- If FTS5 is needed (trigram substring search, bm25), the app must ship its own SQLite: the platform has only FTS3/4. SQLCipher already includes FTS5, so SQLCipher instead of the bundled driver costs only about +0.8 MB on arm64 and gives at-rest DB encryption as well.
- Angus Mail covers every provider feature needed (Gmail X-GM-* via gimap, CONDSTORE/QRESYNC, COMPRESS, IDLE, XOAUTH2) in one library and includes the MIME stack, so mime4j is not needed. Put it behind a small Kotlin interface (suspend functions on Dispatchers.IO) so it can be replaced later.
- With Angus, always set mail.imap(s).connectiontimeout and timeout (both are infinite by default). Keep only a short writetimeout or none, because each one adds a thread. Run IDLE with IMAPFolder.idle() on one dedicated thread for INBOX, not the EXPERIMENTAL IdleManager.
- Never call getContent() on image/* parts with Angus on Android (the java.awt handlers fail); stream parts with getInputStream().
- Ship explicit R8 rules for Angus (provider and handler constructors, MailStreamProvider, angus.activation, plus -dontwarn for java.awt, javax.security.sasl, javax.security.auth.callback and org.graalvm). Keep META-INF/javamail.* and mailcap resources in the APK, and add one instrumented smoke test on a device.
- HTML: use defense in depth. Use jsoup (Cleaner + Safelist, then strip or replace remote src/srcset/background/url() and rewrite cid: to an internal https://cid.invalid/... URL) for display, snippets and FTS text. Then render in a WebView with JS off, file and content access off, setBlockNetworkLoads(true), a CSP meta tag (default-src 'none'; img-src data: https://cid.invalid; style-src 'unsafe-inline'), shouldInterceptRequest that serves only cid parts, Safe Browsing and metrics turned off in the manifest, and links opened outside the WebView after the user confirms.
- Safelist.relaxed() keeps remote https images, so tracking-pixel blocking must be explicit code, not a side effect of sanitizing.
- Credentials: generate one AES-256-GCM key in AndroidKeyStore (try StrongBox, fall back to TEE). Do not set user-auth-required or unlocked-device-required, so background IDLE and sync still work. Encrypt IMAP passwords, refresh tokens and the SQLCipher raw key with it, store only the ciphertext and IV, and set android:allowBackup=false (Keystore keys are not backed up anyway). Do not use security-crypto (deprecated) or Tink.
- An optional biometric app lock should gate the UI only, not the stored keys. Otherwise background sync breaks.
- For token refresh and OAuth, use HttpsURLConnection and org.json (in the platform). An HTTP client library such as OkHttp or Ktor is not needed.
- Do not add WorkManager next to Room 3 (it pulls Room 2). Use the platform JobScheduler for fallback polling and the platform foreground-service APIs for IDLE.
- Do not add DataStore. Keep a few non-secret settings in SharedPreferences or a settings table in the same DB.
- OpenPGP adds about 1 MB of DEX. Put it in a separate Gradle module and use the stable sop-java interface, so a later move to another engine (for example rPGP over JNI) changes only one class.
- For Autocrypt, write your own header parser and peer-state logic (about 200–300 LOC). Thunderbird's Apache-2.0 Autocrypt parser code can be reused with attribution.

## Decisions
### IMAP/SMTP protocol layer
- A) Eclipse Angus Mail 2.0.5 + gimap 2.0.5: + Mature and maintained. Covers IDLE, CONDSTORE/QRESYNC, COMPRESS, XOAUTH2 and Gmail X-GM-*. MIME included. About 314 KB DEX. Permissive license choice (EDL/BSD-3). / - Blocking Java API with a thread per connection. Reflection needs hand-written R8 rules. java.awt image handlers are a trap. No release in 2026 so far. Not yet checked on a device.
- B) Fork Thunderbird :mail:protocols:imap/smtp + :mail:common: + Apache-2.0, already used on Android, Kotlin in parts, OAUTHBEARER. / - Not published; many internal module and third-party dependencies (mime4j, moshi, commons-io, jzlib, jutf7, httpclient5). No CONDSTORE/QRESYNC sync and no X-GM extensions. Fork upkeep.
- C) Own minimal Kotlin IMAP/SMTP (coroutines) + mime4j: + Smallest and cleanest API, full control of IDLE timing and battery, no reflection. / - About 2,500–3,500 LOC plus a large test corpus. High risk from real-server quirks. Slow to reach feature parity.
REC: A. Wrap it behind a small Kotlin MailStore interface so C stays possible later.
### MIME parse/build
- Angus built-in (jakarta.mail.internet): + No extra dependency when Angus is used. / - Older-style API.
- mime4j 0.8.15: + Streaming parser, clean builder, about 149 KB DEX, used by Thunderbird. / - Pulls commons-io. Duplicates Angus.
- Own: + Full control. / - About 800–1,500 LOC of RFC edge cases.
REC: Angus built-in if A is chosen. mime4j only if the protocol layer is your own.
### HTML message display
- jsoup sanitize + hardened WebView: + Defense in depth. Gives remote-content control, link inspection, and plain text for snippets and FTS. / - +200 KB DEX. jsoup docs require core library desugaring (NIO).
- Hardened WebView only (JS off, network blocked, CSP, intercept): + No library. / - No text extraction for search and previews. Remote-content toggles are cruder. Relies only on WebView settings.
REC: jsoup + hardened WebView.
### OpenPGP
- PGPainless 2.0.4 via sop-java (in-app): + Apache-2.0, RFC 9580 v6, used on Android, works after R8 without extra rules. / - About 0.94 MB DEX. BC/PGPainless security advisories need fast updates.
- OpenKeychain OpenPGP API (external app): + Almost no code in the app. / - OpenKeychain is no longer developed. The API lib must be vendored. Users must install a second app.
- rPGP over own JNI: + Modern Rust, MIT/Apache, PQC, proven inside Delta Chat. / - Needs the Rust toolchain, a .so per ABI and an FFI layer you maintain.
- No PGP in v1: + Smallest app. / - Riseup users often expect PGP.
REC: PGPainless 2.0.4 (sop-java API) in a separate module, shipped after core mail works.
### Gmail authentication
- App passwords only: + No OAuth code, no Google registration, no GMS. / - Not available for Workspace, Advanced Protection or security-key-only accounts. Google discourages it. Revoked on password change.
- Manual OAuth PKCE + Custom Tabs (androidx.browser): + About 150–250 LOC, no AppAuth or AppCompat, no GMS. / - Google no longer allows custom URI schemes for Android clients. You need an accepted redirect type and restricted-scope verification for mail.google.com.
- AppAuth 0.11.1: + Proven in Thunderbird and FairEmail. / - No release since 2021. Pulls AppCompat. Same Google registration limits.
- Play services AuthorizationClient: + Google's recommended path, and GMS handles the tokens. / - Needs Google Play services (against the privacy and de-Googled goals). Still needs restricted-scope verification.
REC: v1: app passwords + manual PKCE OAuth behind a feature flag, once the Google client registration question is settled. Do not use AppAuth.
### Database layer
- Room 3.0.3 + SQLCipherDriver or BundledSQLiteDriver: + Compile-checked SQL, Flow invalidation for Compose, @Fts5, KMP-ready. / - KSP build step. Stable only since July 2026.
- androidx.sqlite driver API directly (bundled or SQLCipher): + No codegen, very small API, FTS5. / - Hand-written mapping and your own change notification.
- Framework android.database.sqlite raw: + Zero dependencies, no native lib. / - No FTS5 (FTS4 only). Older SQLite version that depends on the device.
- SQLDelight 2.4.1: + SQL-first and type-safe. / - The Android driver uses SupportSQLite, so FTS5 only via SQLCipher. Extra Gradle plugin.
REC: Room 3.0.3 with SQLCipherDriver.
### At-rest DB encryption
- SQLCipher 4.19.1, random raw key wrapped by a Keystore AES-GCM key that is usable in the background: + Protects against offline extraction and backups. FTS5 included. Only about +0.8 MB compared with the bundled SQLite. / - 5–15% overhead. Does not protect from code that runs as the app after first unlock.
- SQLCipher + unlocked-device-required key (Android 15+ only): + Data stays sealed while the phone is locked. / - Background sync cannot write while locked, so new mail needs a separate small queue. More complex.
- FBE only (bundled or framework SQLite): + Simplest and fastest. / - No protection after first unlock if the files are extracted.
REC: SQLCipher with a Keystore-wrapped raw key that is usable in the background. Keep the unlocked-device-required option for a later 'paranoid mode'.
### Background scheduling and settings libraries
- Platform JobScheduler + SharedPreferences/DB table: + Zero libraries, no Room 2 duplication. / - A little more boilerplate.
- WorkManager 2.12.0 + DataStore 1.2.1: + Familiar APIs. / - WorkManager pulls Room 2 and startup. DataStore is not needed for a few settings.
REC: Platform JobScheduler + SharedPreferences (secrets stay out of it).
### minSdk
- 26: + Widest reach. java.util.Base64. / - Needs androidx.biometric for an app lock, no ImageDecoder, more legacy code paths.
- 30: + Platform BiometricPrompt with setAllowedAuthenticators, ImageDecoder, WebView file access off by default, FBE everywhere. / - Drops Android 8–10.
- 35: + setUnlockedDeviceRequired works reliably. / - Too few devices for a general app in 2026.
REC: 30
### Image library
- None (WebView for inline images, ImageDecoder for previews): + No dependency. / - You write a small thumbnail cache yourself if you need one.
- Coil 3.6.3: + Compose-friendly with caching. / - Several transitive dependencies (including appcompat-resources and exifinterface), and its network stack is not needed.
REC: None.

## Open questions
- Angus Mail 2.0.5 on a real ART device was not tested here; only the JVM smoke test of the R8 output passed. Add one instrumented test (provider lookup, StreamProvider ServiceLoader, multipart parse) before you commit to it.
- Post-login IMAP capabilities of Riseup (CONDSTORE, QRESYNC, COMPRESS=DEFLATE, MOVE, SPECIAL-USE, NOTIFY, METADATA) and Gmail (CONDSTORE, COMPRESS) need one authenticated CAPABILITY from the user. This research did not log in.
- Does WebView still call shouldInterceptRequest for http(s) subresources when setBlockNetworkLoads(true) is set? Test this, or rely on the CSP + intercept path without the block flag.
- jsoup docs require core library desugaring (NIO). Check with lint (NewApi) whether this is still needed at minSdk 30.
- Gmail OAuth for a new non-GMS Android app: which client type and redirect Google accepts in 2026 (custom schemes are blocked for Android clients; loopback is deprecated). Also whether the user will go through restricted-scope verification for https://mail.google.com/.
- Room 3 has been stable only since 2026-07-01. Accept this maturity risk, or use the raw androidx.sqlite driver API?
- Should the recommended minimal set use the combined org.eclipse.angus:jakarta.mail 2.0.5 artifact (API + impl in one jar) instead of jakarta.mail-api + angus-mail? The measurement used the separate jars.
- Is an Angus 2.1.0 final (Jakarta Mail 2.2) planned soon? Only 2.1.0-M1 (Sept 2025) exists.

## Verifier decision feedback
Most recommendations still hold, with these changes. (1) IMAP/SMTP = Angus 2.0.5 + gimap: still holds. Three conditions: set auth.mechanisms=XOAUTH2 explicitly; build a CONDSTORE-only resync path for Gmail (no QRESYNC there); keep BDAT/chunking off until a post-2.0.5 release. Remove the 'never call getContent() on image/*' rule as a crash rule, because those handlers are not registered. The own-client option C is about 4–6k LOC, not 2.5–3.5k, which strengthens A. (2) MIME = Angus built-in: holds. (3) HTML = jsoup + hardened WebView: holds. Use a custom Safelist (allow style attributes and the cid: protocol), not Safelist.relaxed(). Keep setBlockNetworkLoads(true): Chromium still calls shouldInterceptRequest for http(s) and blocks only by forcing cache-only loads. Desugaring is not needed at minSdk 30. (4) OpenPGP = PGPainless 2.0.4 in a separate module: holds only if BC is forced to 1.86 (three OpenPGP CVEs fixed after the pinned 1.84). For Autocrypt, lttrs-autocrypt (Apache-2.0) is a better base to port than starting from zero. (5) Gmail auth: the recommendation is incomplete. Google no longer supports custom schemes for Android clients, so manual PKCE needs an explicit redirect choice: a Desktop client with loopback (against Google's guidance), or a Web client with App Links (needs a static domain file and an embedded secret). Ask the user to choose among: app passwords only in v1, Desktop+loopback, Web+App Links, or GMS AuthorizationClient. Keep 'no AppAuth'. (6) DB = Room 3.0.3 + SQLCipherDriver: holds. SQLDelight is not strictly tied to SQLCipher for FTS5 (a third-party alpha androidx-driver exists), but that does not change the choice. (7) At-rest: SQLCipher with a background-usable Keystore-wrapped key holds. A later 'paranoid mode' can still receive mail while locked: use hybrid public-key encryption, because public-key operations are not restricted by unlocked-device-required. (8) JobScheduler instead of WorkManager: holds on size, but WorkManager and Room 3 coexist by design. More important is the missed FGS rule: IDLE must run as a specialUse foreground service (as FairEmail and Thunderbird do), not dataSync, which has a 6 h/24 h limit at target 35+. (9) minSdk 30 and no image library: hold. Coil's 'network stack' con is wrong, but its other dependencies justify skipping it. (10) Version table: change kotlin-stdlib to 2.4.21. Add android:dataExtractionRules in addition to allowBackup=false.
